# Отчет по прпактическому заданию модуля 2 vk education

## ЧТо реализовано

| Метод | Путь | Описание |
|---|---|---|
| POST | /login | Вход по email и паролю, выдача сессии в cookie |
| POST | /register | Регистрация: проверка email/пароля, хэш bcrypt, 409 при дубликате |
| GET | /me | Возвращает email текущего пользователя (по токену из cookie) |
| POST | /refresh | Обмен refresh-токена на новую пару (access + refresh) |

## Ответы сервера (8 негативных случаев)

| № | Случай | Ожижаемый ответ| Отметка о реализации |
|---|---|---|---|
| 1 | Вход с неверным паролем | 401, одинковый с несуществующим пользователем | Реализовано |
| 2 | Запрос без токена | 401 | Ревлизовано |
| 3 | Запрос с "протухшим" токеном | 401 с причиной | Нереализовано |
| 4 | Обращение к чужому резюме | 403 | Нереализовано |
| 5 | Загружаемый файл больше предела | 413 | Нереализовано |
| 6 | Файл неподдерживаемого формата | 415 | Нереализовано |
| 7 | Файл без текста | 422 с причиной | Нереализовано |
| 8 | Повторный запуск того же анализа | тот же идентификатор задачи | Нереализовано |
| 9 | Регистрация с занятым email | 409, `email_taken` | Реализовано |

## Принятые ограничения

1. Сессии хранятся не в БД или Redis , а в памяти.
 - достаточно для учебного проекта, при презагрузке контейнера все сессии сбрасываются
 - для прода необходимо завести Redis (можно использовать как кэш, чтобы лишний раз не ходить в БД) и таблицу Sessions в БД

 2. Два токена (access + refresh).
   - Как реализовано: access живёт 15 минут (на сервере), refresh — 30 дней. При `/refresh` оба токена ротируются.
   - Ограничение: сессии хранятся в памяти (не в Redis). При перезапуске контейнера все токены сбрасываются

3. **Нет ограничения частоты попыток входа**.
   - для учебного проекта не критично.
   - можно внести rate limiting (например, через `golang.org/x/time/rate` или middleware).
